# Offer-selection rules — learned from the operator's own corrections

**Template.** Copy to `prompts/read-rules.md` and let `voice` fill it.
`read-rules.md` is gitignored, because it describes one operator's services and
one operator's judgment. This file is the public starting point and stays
generic.

---

## What this file is

`prompts/read-the-person.md` is the standing instruction for forming a thesis
about a prospect: what they are trying to do, what is in the way, what an hour
of the operator's time would produce. It is written once and versioned.

This file is different. It accumulates, one rule at a time, from corrections the
operator typed against real drafts, and only when he decides a correction is a
rule rather than an example.

The split matters. A correction about WORDING goes to `prompts/voice.md`, which
the drafting stage reads. A correction about WHICH OFFER a note should make goes
here, because the offer is chosen by `read` before a word is drafted. Filing an
offer-selection correction as a voice rule is how the same pitch error gets
corrected four times and retained none of them.

## What belongs here

- How to decide which service fits a person from thin evidence.
- Which evidence to weight: what someone's own output is mostly about, versus
  the most technically interesting fact on file.
- What the obvious next step is for someone in a given situation.
- Which pitches are a reach, and the tell that one is being reached for.

## What does not

- Wording, register, length, salutation, the shape of the ask. Those are voice.
- A fact about one prospect. The rule underneath it might belong here; the fact
  does not.
- A pitch to copy. "Offer X to CIOs" is a phrase, and a phrase becomes every
  note's answer. State the reasoning, not the conclusion.
